## 1. 技术选型与理由

| 方面 | 选型 | 理由 |
|------|------|------|
| 语言 / UI | Kotlin 2.2.10 + Jetpack Compose（BOM 2026.02.01，Compose 1.10.4）+ Material 3 | 模板既定；单 Activity + 全 Compose |
| 构建 | AGP 9.2.1 / Gradle 9.4.1 / JDK 17，compileSdk 36.1，minSdk 31，targetSdk 36 | 模板既定；minSdk 31 可用 `ImageDecoder`/系统照片选择器等新 API |
| 导航 | `navigation-compose 2.9.0`，字符串路由 | feature 只依赖 `AppNavigator` 接口，互不引用 |
| 网络 | Retrofit 3.0.0 + OkHttp 5.1.0 + `kotlinx-serialization-json 1.9.0` | Retrofit 3 要求 OkHttp 5；序列化用 kotlinx（无反射、`ignoreUnknownKeys`） |
| 图片 | **自研 `ImageLoader`（OkHttp + BitmapFactory + LruCache）** | 缓存里的 Coil 2.7 面向 OkHttp 4，与 OkHttp 5 混用有运行期不兼容风险；自研同时便于统一占位策略 |
| 视频 | **框架自带 `VideoView` + `MediaPlayer`（AndroidView 包装）** | 缓存里没有 media3/ExoPlayer；框架播放器零依赖，支持 HTTP + Range 即可满足 C2 |
| DI | **手工容器 `AppContainer` + `appViewModel {}`** | Hilt 未在依赖缓存中，且需 KSP/注解处理，与 AGP 9 + Kotlin 2.2 有版本耦合风险；本项目依赖图很浅，手工容器更简单可读 |
| 分页 | 自研 `PagedList<T>` + `PagedState<T>` | 不引入 Paging 3；把「每页 20 / 距底预加载 / 四态 / 追加失败不清空」收敛成一个小类 |
| 持久化 | DataStore Preferences（登录态、搜索历史） | 轻量 KV，够用；AI 对话仅内存 |
| 本地状态 | 单一 `AppContainer` 内的若干 Store（`InteractionStore` / `UnreadCountCenter` / `PublishDraft`） | 跨页面共享的「状态流」集中管理，避免各页各存一份导致返回后状态回跳 |

**明确不引入**：Hilt、Coil、Media3、Paging3、Room、Accompanist、任何测试框架。
新增依赖前请先确认它在 `~/.gradle/caches/modules-2/` 里已有（当前构建走 `--offline`）。

## 2. 目录结构与职责边界

```
com.xiaohongshu.app
├── XhsApplication.kt          容器入口（不做网络请求，避免拖慢冷启动）
├── MainActivity.kt            单 Activity：edge-to-edge + 主题 + 注入容器 + Toast 宿主
├── di/AppContainer.kt         依赖容器 + LocalAppContainer + appViewModel {}
├── core/                      ① 与业务无关的公共能力（谁都可以用，但不依赖 feature）
│   ├── design/                设计 Token：XhsColor / XhsType / Dimens / XhsTheme
│   ├── ui/                    设计系统组件：按钮 / 顶栏 / 底栏 / 状态 / 弹层 / 图片 / 瀑布流 / Toast
│   ├── net/                   ApiResult / ApiEnvelope / ApiClient / 拦截器 / 错误码
│   ├── image/ImageLoader.kt   图片加载与两级缓存
│   ├── list/PagedList.kt      分页引擎 + 近底部观测
│   ├── interact/             **InteractionStore**（点赞/收藏/关注的乐观更新与跨页一致）
│   ├── notify/                **UnreadCountCenter**（15s 轮询、角标、乐观递减）
│   ├── auth/LoginGate.kt      **登录拦截**（runOrDefer：未登录暂存动作，登录后补执行）
│   ├── publish/PublishDraft.kt 发布草稿（E1→E2→E3 交接）
│   └── util/Formatters.kt     时间与计数格式化
├── data/                      ② 取数与映射（只吐 domain model + ApiResult，不含 UI 状态）
│   ├── api/                   Retrofit 接口（User/Post/Comment/Like+Collect+Follow/Notification/Ai/Upload）
│   ├── dto/                   与服务端字段一一对应的可序列化模型
│   ├── mapper/Mappers.kt      DTO → domain（时间解析、比例、文案兜底都在这里）
│   ├── local/                 SessionManager（登录态）/ SearchHistoryStore
│   └── repo/                  Repository：取数 + 映射，不持有界面状态
├── domain/model/Models.kt      UI 层模型（Note / Comment / User / NotificationItem / Paged / …）
├── navigation/                路由表 / AppNavigator / NavHost / MainScaffold
└── feature/<area>/            ③ 各业务页面（**彼此零引用**）
```

**边界规则（重要）**
- `core` 不得 import `feature`；`feature` 之间不得互相 import。
- `feature` 只能依赖：`core/*`、`domain/model`、`navigation/AppNavigator`、`di/LocalAppContainer`。
- `feature` **不得**直接使用 `data/api` 或 `data/dto`（走 Repository）。唯一例外：`NotificationCategory` 这类纯枚举常量（在 `data/dto` 里，已作为导航参数使用）。
- 需要新增跨页面共享的状态时，加在 `core/<域>/` 并在 `AppContainer` 注册，而不是在页面里 `remember`。

## 3. 写一个页面的标准骨架

每个 feature 只暴露 `XxxRoute(navigator: AppNavigator, ...)` 作为入口（已在 `AppNavHost` 注册好），
其余全部私有。**不要改 `AppNavHost` 的签名**，如需带参请在 `Routes` 里加。

```kotlin
package com.xiaohongshu.app.feature.home

@Composable
fun HomeRoute(navigator: AppNavigator) {
    val vm: HomeViewModel = appViewModel { HomeViewModel(it.postRepository, it.interactionStore, it.loginGate, it.toastController) }
    val state by vm.state.collectAsStateWithLifecycle()

    HomeScreen(
        state = state,
        onNoteClick = navigator::toNote,          // (postId, isVideo)
        onLikeClick = vm::toggleLike,
        onSearchClick = navigator::toSearch,
    )
}

/** 无状态内容层：方便 Preview，也强制把状态提升到 VM。 */
@Composable
private fun HomeScreen(state: HomeUiState, onNoteClick: (Long, Boolean) -> Unit, /* ... */) { /* ... */ }
```

- **状态提升**：`Route`（有状态，接 VM）→ `Screen`（无状态，接 state + 回调）。不要在有状态层写布局。
- **ViewModel**：继承 `androidx.lifecycle.ViewModel`，用 `viewModelScope`。构造参数直接写依赖，靠 `appViewModel { }` 注入。
- **一次性事件**（Toast、导航）用回调从 `Route` 触发，**不要**用 `SharedFlow` 硬塞进 state（列表状态会随之抖动）。全局 Toast 统一走 `AppContainer.toastController.show(...)`。

## 4. 必须遵守的规范（验收会看）

### 4.1 设计 Token —— 一律取自 `core/design`，禁止写魔法数
- 颜色：`XhsColor.Red(#EA3F4A)` / `Text1(#333)` / `Text2(#999)` / `Text3(#CCC)` / `Divider(#EEE 0.6dp)` / `Bg(#FFF)` / `BgGray(#F5F5F5)` / `Dark(#1A1A1A)` / `Black` / `Scrim(60%黑)`。
  深色沉浸页（C2/C3）用 `XhsColors.divider` 等随主题切换的访问器，而不是硬编码。
- 字号：只用 `XhsType` 的 8 档（11/12/14/15/16/17/20/24）+ 具名 style。字重只有两档：400 / 600（`emphasis = true`）。
- 尺寸/间距：`Dimens`（4/8/12/16/24/32；页边距 16；顶栏 44；频道栏 40；详情顶/底栏 56；视频底栏 44；底 Tab 45；＋钮 60×45）。
- 底 Tab（**无图标、纯文字**，与原版一致）：栏高 45、5 等分每格 82.3；未选 16sp `TabInactive(#8C8C8C)`、选中 17sp 粗 `Text1(#333)`（`XhsType.bottomTabUnselected / bottomTabSelected`）；＋ 为 60×45 圆角 12 满高红块；五格点击**无涟漪**（`clickableNoRipple`，原版为瞬时切换）。
- 圆角：卡片 8、弹层/弹窗 12、chip/胶囊/徽标 = pill。
- 头像档位：24 / 36 / 48 / 60 / 108（`Dimens.avatarX`）；图标档位 12 / 16 / 20 / 24，互动图标 30（**仅**详情/视频底栏）。
- 瀑布流卡宽公式 `(W−12)/2`、三入口卡 `(W−32)/3` —— 用 `Waterfall.cardWidth / entryCardWidth`，**禁止写死像素宽**。
- 触控热区一律 ≥44dp（`Dimens.minTouchTarget`）。

### 4.2 列表四态必须齐全（B4-1 ~ B4-5，适用于**所有**瀑布流/列表）
用 `PagedList<T>` + `XhsListStateHost` + `XhsListFooter`，不要各写一套。
每页 20 条；距底约 6 项触发 `loadMore()`；到底显示「没有更多了」且不再发请求；**追加失败不清空已加载内容**，只弹全局 Toast；首次失败整页错误态 + 「重试」。

### 4.3 互动一律走 `InteractionStore`（D1/D2）
点赞/收藏/关注的**乐观更新 + 失败回滚 + 跨页一致**已在 `InteractionStore` 实现。

> ⚠️ **最容易踩的坑**：`merge()` 的返回值**只能用于渲染**，绝不能当成 `toggleXxx()` 的入参。
> `toggleXxx(serverNote)` 用入参的 `liked`/`likeCount` 作为**服务端基准**来算增量；
> 若传入已合并过的值，基准里已经含了旧增量，会被重复叠加，导致计数永久偏移。
> 参数名特意叫 `serverNote`/`serverComment` 就是为了让误用在阅读时显形。

```kotlin
// ✅ 正确：raw 是服务端原值，display 是合并后的渲染值
val display = interactionStore.merge(rawNote)          // 渲染用
Card(note = display, onClick = {
    if (!loginGate.runOrDefer { vm.toggleLike(rawNote) }) navigator.toLogin()
})

// ❌ 错误：把 merge 的结果又喂回 toggle，计数会偏移
interactionStore.toggleLike(interactionStore.merge(rawNote))
```

- 列表渲染用 `mergeAll(list)`（VM 里做一次），详情用 `merge(note)`。
- `toggleLike/toggleCollect/toggleFollow/toggleCommentLike` 都是 `suspend`，失败时自己弹 Toast 并回滚。
- **不要**自己写 `likeCount + 1`；也不要为此在 VM 里另存一份计数。
- 关注态合并读取用 `interactionStore.followedOf(authorId, serverValue)`。

### 4.4 登录拦截（A2 → A3 → A6）
- 需登录的写操作与入口：用 `loginGate.runOrDefer { 动作 }`；返回 false 时 `navigator.toLogin()`。
  **不做 Toast 提示**（线框明确）。登录成功后 `navigator.popLogin()` 会补执行被拦截的动作并弹回来源页。
- 入口类拦截（＋ / 消息 / 我）只需判断 `sessionManager.isLoggedIn`。
- 登录态读取：`LocalAppContainer.current.sessionManager.state.collectAsStateWithLifecycle()`。

### 4.5 占位素材约定
`ic_placeholder`（图标）与 `ic_placeholder_illus`（插画）是**全项目唯一**的缺失素材占位，验收时靠它一眼看出待替换项。
- 缺失图标 → `XhsIconButton(R.drawable.ic_placeholder, ...)`，插画空态 → `XhsIllustrationSlot()`。
- 已有真实素材的图标请用它们（`R.drawable.ic_home / ic_assistant / ic_notify / ic_heart / ic_heart_filled / ic_star / ic_star_filled / ic_comment / ic_search / ic_more / ic_close / ic_chevron_left / ic_chevron_right / ic_publish / ic_live / ic_male / ic_female / ic_about / ic_red / ic_logo`）。
- 结构性控件已用 Canvas 精确绘制（`XhsPlusGlyph` / `XhsMenuGlyph` / `XhsPlayGlyph` / `XhsPersonGlyph` / `XhsCheckCircle`），不要用占位素材替代。
- 图片一律用 `XhsAsyncImage` / `XhsAvatar` / `XhsCoverImage`（内部走 `ImageLoader` + 统一占位）。

### 4.6 文案与计数规则
- 计数为 0 → 显示文字标签（「赞」「收藏」「评论」）；>0 → 数字；≥10000 → `1.2万`。用 `XhsCountText` / `Formatters.formatCount`。
- 角标 >99 → `99+`（`XhsCountBadge` 已处理）。
- 时间：详情页用 `formatNoteTime`（今天 10:16 / 昨天 10:16 / 2026-09-14），评论与通知用 `formatRelative`（3分钟前 / 2小时前 / 昨天 / 09-14），会话列表用 `formatConversationTime`。
- Toast 统一 2.5s 屏幕中心（`toastController.show`）；请求超时统一 15s（AI 70s，已在 `ApiClient` 配好）。

### 4.7 空态与错误态文案（线框已定稿，不要自创）
| 场景 | 文案 |
|------|------|
| 列表空（首页/关注流） | 「还没有笔记，快来发布第一条吧～」 |
| 关注流空 | 「还没有关注的人，去发现逛逛吧」 |
| 搜索无结果 | 「暂无相关内容，换个关键词试试」 |
| 笔记/收藏/点赞空 | 「暂无笔记」/「暂无收藏」/「暂无点赞」 |
| 评论空 | 「还没有评论哦」 |
| 通知空 | 「暂无消息」 |
| 列表加载失败 | 「加载失败，请稍后重试」+ 重试 |
| 图文详情失败 | 「笔记加载失败」+ 重试（白底灰字） |
| 视频详情失败 | 黑底灰字，**无重试按钮**（返回后重进） |
| 网络异常 | 超时「请求超时，请检查网络」/ 其他「网络异常，请稍后重试」 |
| 相机拒绝 | 「未授权相机，可从相册选择」 |

## 6. 构建与联调

```bash
cd client

# 1) 启动 mock server（另开一个终端；emulator 经 10.0.2.2 访问宿主）
cd mockserver && PUBLIC_BASE=http://10.0.2.2:8787 node server.mjs

# 2) 编译 / 装 APK（当前依赖已全部在本地 Gradle 缓存，可离线）
cd .. && ./gradlew :app:assembleDebug --offline

# 3) 指向真实后端时覆盖 Base URL（无需改代码）
./gradlew :app:assembleDebug -Pxhs.baseUrl=http://192.168.1.10:8080/
```

- Base URL 默认 `http://10.0.2.2:8787/`，来自 `BuildConfig.XHS_BASE_URL`。
- mock server 支持故障注入以便验证异常态：请求头 `X-Mock-Fail: 1`（500）/ `401`（登录失效）/ `timeout`（20s，触发客户端 15s 超时），`X-Mock-Delay: <ms>` 调延迟。
- 明文 HTTP 已通过 `res/xml/network_security_config.xml` 放开（接真实 HTTPS 后应收紧）。

## 7. 页面实现清单（照着线框图逐屏对齐）

**A 游客与登录（WS-Auth）**
- A1 首页游客态：顶栏左侧 ☰（登录后变点点气泡）、底部登录悬浮条「🔒 登录后体验更多功能 [登录]」、＋ 灰色、消息无角标。
- A3 登录页：返回 + 右上「帮助」、居中 LOGO（`ic_logo`）+ 标语、用户名/密码输入、全圆角主按钮、协议勾选（`XhsCheckCircle`）、底部「没有账号？注册」。
- A4 注册页：4 个输入（用户名 3-20 必填 / 密码 6-20 必填 / 昵称选填 ≤20 / 手机号选填 `1[3-9]\d{9}`）；**成功不自动登录**，Toast「注册成功，请登录」→ 回 A3 并预填用户名。
- A5-1 失败态：错误条在表单**上方**（`XhsFormErrorBar`），已填内容保留；A5-2 提交中：按钮禁用文案「登录中...」，此态 ← 不可返回。
- A6：登录成功 Toast「登录成功」+ `popLogin()` 弹回来源页。
