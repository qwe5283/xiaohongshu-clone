# 案例复盘（诊断新问题前先读这个）

每条都是本仓库真实踩过的：症状 → 怎么查出来 → 根因 → 修法 → 教训。
金额单位都是 **dp @ 24dp 画布**，因为这正是验收时肉眼与量测的口径。

---

## 1. 心形比邻居细 17%（1.5dp vs 1.8dp）

- **症状**：详情页底栏「点赞/收藏/评论」三个图标并排，心形明显细。
- **查法**：`audit.mjs` 量出 `ic_heart` 1.50dp、`ic_star`/`ic_comment` 1.80dp。
- **根因**：心形用的是 **16 视口**，`width=24dp` → 1 个视口单位 = 1.5dp；它在 16 栅格里写的是
  1.0 单位描边，落到 24dp 就是 1.5dp。而星形/评论是 24 视口 1:1，写的 1.8 单位就是 1.8dp。
  —— 同一套图标混了 16/20/22/24/48/960/1024 七种栅格，**换算后线宽就散了**。
- **修法**：**不要改路径**。整条路径等比缩进 24 视口（×1.5，圆弧半径一起缩），再叠一条
  `strokeWidth="0.3"` 的同色描边 —— 描边是真实偏移（两侧各 +0.15），环带精确 1.5 → 1.8dp，
  原形状一点没动，外缘只扩 0.15dp。命令：`convert.mjs thicken ic_heart.xml --from 1.5 --to 1.8`。
- **教训**：视口不一致是线宽偏差最常见的根因。先 `audit.mjs` 看「视口」列，再决定缩放还是叠描边。

## 2. 点赞切换会跳（1.7dp 变大 + 1.3dp 上移）、星形倒角不一致

- **症状**：点一下赞，心形变大并上跳；用户还发现实心五角星是尖角、描边星是圆角。
- **查法**：比对两个文件的图形外缘 bbox——`ic_heart` 20.00×18.00 @(2.00,3.00)，
  `ic_heart_filled` 21.00×19.67 @(1.50,1.71)：**尺寸和位置都不一样**；
  `ic_star_filled` 尺寸对了但高了 0.5dp。倒角差异来自 `ic_star_filled` 是另一版尖角路径。
- **根因**：填充版是**另一份手画/描摹的路径**，不是描边版的外缘。
- **修法**：填充版必须用描边版的**同一条外轮廓**：
  - 心形：`ic_heart_filled` 直接用 `ic_heart` 的第 2 条（外）轮廓 + 同样的 0.3dp 外扩描边；
  - 星形：`convert.mjs pair ic_star.xml --out ic_star_filled.xml`（取面积最大的轮廓）。
  修完后两个文件的 bbox 逐字相同（20.31×18.30 @(1.84,2.85) / 20.00×19.00 @(2.00,2.50)）。
- **教训**：**配对图标（描边↔填充）必须共用外缘**，否则切换态会跳。验收时把两个 bbox 打出来对比。

## 3. 助手气泡底部有两条发丝裂缝

- **症状**：放大看 `ic_assistant` 底部描边里有两条头发丝宽的白色缝隙。
- **查法**：看子路径——5 段里 3 段是坐标量级 0.01 的**碎片**；再看填充规则，写的是
  `fillType="evenOdd"`。把 5 段分别染色渲染，发现第 1 段是个**矩形补丁**，正压在外框底边上。
- **根因**：这是**描摹产物**：外框其实是一条螺旋状路径（绕外圈后折回内圈，接缝处断开），
  有人拿个矩形把断口糊上了。evenOdd 规则下"补丁 ∩ 环带"**相互抵消**，于是正好在补丁两侧露出缝。
- **修法**：重绘。把外框几何拟合出来——圆心 (11.73,12.0)、外 R=9 的圆，左下角补成直角
  （左 x=2.73、下 y=21.0，两处正好与圆相切），中线用 `strokeWidth="1.8"` 表达：
  `M3.63 20.1L3.63 12A8.1 8.1 0 1 1 11.73 20.1Z`。外缘 18.0×18.0dp 与原图逐字相同。
- **教训**：**描摹路径会带补丁、碎片、自环**。排查顺序：数子路径 → 量每段点数 → 分别染色渲染 →
  看填充规则（evenOdd 最容易被重叠抵消坑到）。修不如重画。

## 4. 扫帚：线宽量错了，导致归一化基准也错

- **症状**：按"源线宽 78.8 单位"归一化后，扫帚占位缩到 17.0×17.5dp（比别的小一圈）。
- **查法**：光栅化后逐列扫墨迹段，实测线宽只有 **1.45~1.50dp**，不是预期的 1.8 → 反推源线宽
  应是 **64 单位**（iconfont 常规值，64/1024 = 6.25%），78.8 是错的。
- **根因**：**量测工具的展平器不认 `s/S`、`t/T` 平滑曲线命令**，把 `扫帚.svg` 里那段 `t` 整个丢掉了，
  轮廓不完整 → 近邻轮廓对的距离被算大。修好展平器（补上"上一控制点关于当前点反射"）后一切正常。
- **修法**：源 SVG 已不在仓库，就地改 XML：先按目标占位缩放（`convert.mjs rescale --art 19.5`），
  再叠 `strokeWidth="0.17"` 补齐 → **占位 19.1×19.7dp + 线宽 1.79dp，两个目标同时达成**。
- **教训**：① 量线宽前先确认工具支持 `s/S`/`t/T`（本 skill 的 `lib.mjs` 已支持，别退回旧写法）；
  ② "源线条比本套粗，只能二选一"这种结论，先怀疑量测；③ 真要两个都要时：
  **先按占位缩放，再叠描边补线宽** —— 缩放改不了线条比例，但描边可以。

## 5. chevron 1.5dp、close 2.0dp、☰ 三个调用处三个线宽

- **症状**：`ic_chevron_*` 1.5dp、`ic_close` 2.0dp，都不在 1.8dp 主线上；☰ 更离谱——它由 Canvas
  字形 `XhsMenuGlyph` 画，线宽 = `尺寸 × 0.1`，于是在 16dp 处 1.6dp、24dp 处 2.4dp、29dp 处 2.9dp。
- **查法**：`audit.mjs` 一眼看出 chevron/close 偏离；☰ 则要读 `XhsGlyphs.kt` 才看到那个比例系数。
- **修法**：
  - chevron：原来是"丝带字形"，改写成**「中点折线 + strokeWidth=1.8 + miter 折角」**
    （中线 (15,4.5)→(7.765,12)→(15,19.5)，外缘 9.0×16.8dp，原 9.0×16.5dp）；
  - close：两条对角线 `M18 6L6 18M18 18L6 6` + `strokeWidth=1.8`（外缘 13.8×13.8dp，原 14.0×14.0）；
  - ☰：建成资源 `ic_menu`（3 条线中线 x 2.4~21.6、y 5.28/12/18.72 + 1.8dp），三处调用改用它。
- **教训**：① 简单线形字形**用"中线 + strokeWidth"表达最省事**，还便于以后调粗细；
  ② **凡是在代码里按"尺寸×比例"画线宽的字形，落到不同调用处必然宽窄不一** —— 要么建成资源，
  要么显式传线宽。本项目剩下的 `XhsPlusGlyph` / `XhsCheckCircle` 仍属这一类，改之前先确认是否值得。
  ③ 工具类小字形（close / chevron / menu / more / play）**只统一线宽、不动占位**：它们的尺寸是线框定的，
  挤在顶栏和列表行里，放大反而错。

## 6. 把 .svg 放进 res/drawable —— 直接构建失败

- **症状**：`./gradlew :app:processDebugResources` 报
  `The file name must end with .xml or .png`。
- **根因**：Android 运行时不认 SVG，`res/drawable/` 只收 `.xml`/`.png`；aapt2 连文件名编码都挑，
  中文名文件打不开（实测）。
- **修法**：源 SVG 放 `client/docs/assets/`（或前端图标目录），转成 `ic_xxx.xml` 再放进 drawable。
- **教训**：下载素材后**先别放进 drawable 目录**；转换 + 改名后再放。资源名只用 `[a-z0-9_]`。

## 附：测量口径与陷阱速查

| 字形类型 | 线宽怎么量 | 说明 |
|---|---|---|
| 纯描边路径（只有 strokeColor/strokeWidth） | 就是 `strokeWidth` | 最省事、最可验证 |
| 双轮廓环带（nonzero，两条反向轮廓） | 两条近平行轮廓间距 + `strokeWidth` | 判据：p10~p90 离散度 < 中位 40%；**还要确认轮廓之间是墨迹**（绕数≠0），否则量到的是两个部件之间的空隙 |
| 自环单轮廓（如扫帚外框） | `2 × 面积 ÷ 周长` | 前缀面积最大幅值显著大于净面积即为自环 |
| 实心字形 | 无"线宽"概念，只看占位 | 别硬套 1.8dp |
| 插画（子路径 > 20） | 不适用 | `audit.mjs` 会标"插画"并跳过 |

**陷阱**：

- 光栅扫描量"水平墨迹段长度"会把斜线的线宽算大（斜线被水平切，run = 线宽 / sinθ）；只在纯水平/纯垂直线段上可信。
- 多部件字形量出多组近平行间距时，`audit.mjs` 报「多处量值」而**不下结论** —— 这时按构造判断
  （厚度写进路径时：源单位 × 缩放比）或看对照图目检。
- `fillType="evenOdd"` 与 nonzero 的渲染结果可能完全不同；描摹产物在这两种规则下的差异尤其大。
- 多子路径渲染对照图时**不能用简单的并集**：环形图标会被填成实心，看着像改坏了。
  用 `contact-sheet.py`（内部按 nonzero 分正负绕向、evenOdd 走 XOR）。
